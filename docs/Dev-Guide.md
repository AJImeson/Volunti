* devdocs

- Depending on which role you have, there are separate .md files where documentation of tech stacks should be written down and decided for each role. This will increase the knowledge for each team member in understanding what type of environment the others (and also remind yourself of your own) will be working in.

- This can be considered as an agreement, whereas we acknowledge and "pledge" ourselves to certain stacks

* devlogs

- Depending on which role you have, there are separate .md files where documentation of what has been completed/struggled with/or thought of during the session/day. 

- Example could be:

    2026-03-13
    Finished the sidebar on front page, can't test properly since there is a pipeline bug. Need to speak to Axel so he can have a look at it 

- The devlog doesn't have to be this specific or fancy, just so there is some documentation ready in the repo
